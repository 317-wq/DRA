# MVP-0.6 · 历史与追问

> 基线：PROJECT.md v1.6

> 日期：2026-10-21

> 已同步至 PROJECT.md v1.6（追问存储与接口）

## 1. 本版范围

**包含什么**：

1. **追问引擎**：基于父研究的证据回答新问题，默认**不重新检索**。
2. **证据选择**：用 BM25 从父 run 的来源里选 Top-k（复用知识库的分词实现）。
3. **引用一致**：沿用父报告编号（[3] 在追问里仍指同一来源），无效编号丢弃。
4. **落盘**：`runs/<parent>/followups/<id>/{answer.md, meta.json, trace.jsonl}`，父目录维护 `followups.json` 索引。
5. **CLI**：`dra ask "<问题>" [--run <id>] [--k 6]`。
6. **界面**：报告页新增「追问」tab，输入问题、看历史追问与答案。
7. **几乎零搜索额度**：只调用一次 LLM，不碰 Tavily。

**不包含什么**：

- 追问的追问（树形多层）——目前是父报告下的一层
- 主动补充检索（如果证据不够，只如实说不够，不偷偷再搜）
- 追问结果沉淀到知识库（下一步可做）

## 2. 本版用户路径

> `dra ui` → 打开一次已完成的研究 → 切「追问」
> → 输入「这些方案里谁的延迟最低？」
> → 约 10 秒得到 400 字回答，引用沿用父报告编号
> → 历史追问留在列表里，随时点开

或命令行：

> `dra ask "那成本呢？" --run <run_id>`

## 4. 本版要实现的模块功能

- [x] **证据选择**：BM25 选 Top-k，命中为 0 时退化为前 k 篇
- [x] **追问生成**：单次 LLM 调用，300–800 字，强制引用
- [x] **引用保持**：`renumber=False`，保留父编号；无效编号丢弃并计数
- [x] **落盘与索引**：answer / meta / trace / followups.json
- [x] **CLI**：`dra ask`
- [x] **API**：列表、发起、读取（含渲染 HTML）
- [x] **UI**：追问 tab、历史列表、答案展示
- [x] **错误处理**：无报告 409、父 run 还在跑 409、不存在的追问 404

## 6. 本版风险与待办

- **证据不足是常态**：父报告只有 4–12 篇来源，追问超出范围时只能如实说“不够”；需要更强回答时应重新开一次研究。
- **单层追问**：不能对追问继续追问；0.7 可做树形或“追问也能引用其他 run”。
- **无补充检索**：刻意不做，避免额度与口径漂移；如需要可加 `--search` 开关（下一版评估）。
- **UI 未自动化**：仅 API 与引擎测试。

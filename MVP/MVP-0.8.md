# MVP-0.8 · 质量约束（数字必须可回指）

> 基线：PROJECT.md v1.8
> 前置版本：MVP-0.7（证据质量）
> 日期：2026-10-21
> 状态：**已完成**（单测 + 一次小规模真实运行验证）
> 已同步至 PROJECT.md v1.8（写作约束与校对闸门）

## 1. 本版范围

**包含什么**：

1. **写作硬约束**：报告里的具体数字必须逐字出现在证据摘录中；找不到就写“资料未给出具体数值”或改成定性表述。
2. **写后本地核验**：写完立即用 `evaluate` 算数字可核验率，低于阈值（默认 75%）触发一次校对。
3. **带证据的校对**：把“未核验数字 + 对应来源摘录”一起给模型，只修数字，保留结构与引用。
4. **验收闸门**：修复稿必须同时满足
   - 可核验率比原稿提升 ≥5 个百分点；
   - 引用数量 ≥ 原稿的 60%；
   - 长度 ≥ 原稿的 60%。
   否则丢弃修复、保留原稿，并记录提示。
5. **自动评估**：每次研究结束写 `eval.json`，`trace` 里记录 `write.verify` / `write.verified`。

**不包含什么**：

- 逐句事实核查（LLM-as-judge，成本高）
- 对“定性表述是否夸大”的判断
- 修复失败后的二次修复（只做一次，避免无限循环）

## 2. 用户路径

> `dra run "主题" --max-sources 6 --max-rounds 1`
> → 写作完成后本地算数字可核验率
> → 低于 75% 时带证据打回一次；修复稿不达标就保留原稿
> → 结束提示里能看到可核验率与评分
> → `dra eval` / 页面「质量」tab 复核

## 3. 相对基线的增量

- 架构 / 模块改动：`_write` 增加“核验 → 校对 → 验收”流程；新增 `repair_messages`。
- 配置：`DRA_MIN_NUMBER_SUPPORT`（默认 0.75）。
- 接口：`eval.json` 由研究流程自动生成；事件新增 `write.verify`、`write.verified`。
- 其他：版本 0.8.0。

## 4. 本版要实现的模块功能

- [x] **写作约束**：数字逐字来自证据，禁止换算/估算/四舍五入
- [x] **核验**：复用 `evaluate_report`，不额外调用模型
- [x] **校对提示**：只改数字句、保留全部引用、长度不得明显缩水
- [x] **验收闸门**：可核验率、引用数、长度三项同时满足才采纳
- [x] **自动 eval.json** 与 trace 事件
- [x] **测试**：修复被采纳 / 被拒绝两条路径

## 5. 本版验收标准

- [x] 未达阈值时会触发恰好一次校对
- [x] 校对稿丢失引用或大幅缩短时被拒绝，原稿保留
- [x] 采纳修复后可核验率提升，且引用不大量丢失
- [x] `eval.json` 自动写入，`dra eval` 可复算
- [x] 正常写作（数字已在证据中）不触发校对
- [x] 90 个离线单测通过

## 6. 本版风险与待办

- **闸门是启发式**：可核验率依赖数字字符串匹配，单位换算/四舍五入仍会误报。
- **一次修复**：修复失败就保留原稿，不追求“必须变好”。
- **仍可能过度定性**：严格规则下模型可能少写数字；本次实测未出现（可核验率 98.1%）。
- **未约束定性夸大**：例如“显著领先”这类判断仍可能缺依据。

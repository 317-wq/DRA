# MVP-0.7 · 证据质量

> 基线：PROJECT.md v1.7
> 前置版本：MVP-0.6（追问）
> 日期：2026-10-21
> 状态：**已完成**（评估器、来源分级、CLI 与页面验证）
> 已同步至 PROJECT.md v1.7（证据质量字段与评估接口）

## 1. 本版范围

**包含什么**：

1. **来源分级**：采集时给每条证据记录 `tier`（3 一手 / 2 专业媒体 / 1 一般 / 0 自媒体）、
   `tier_label`、`quality`（0–100）。
2. **本地评估**：`dra eval <run_id>` 计算引用覆盖、数字可核验率、来源多样性，
   不调用模型、不消耗搜索额度。
3. **基线**：`dra eval --all` 对全部历史报告跑一遍，给出均分/区间/等级分布。
4. **页面「质量」tab**：分数、等级、四项指标、警告、未在引用来源中找到的数字。
5. **提示词提示来源等级**：分析与写作时证据行会带“（一手 / 自媒体）”，让模型知道该信谁。

**不包含什么**：

- 用 LLM 做 claim-level 事实核查（成本高，先做可解释的确定性指标）
- 自动拦截低质量报告（只评估，不阻断）
- 跨报告一致性（同一主题多次研究的结论对比）

## 2. 本版用户路径

> `dra eval`（最近一次）
> → 分数 / 等级 / 引用覆盖 / 数字可核验 / 来源域名数
> → 未核验数字列表
> → `dra eval --all` 看整体基线
> → 或在 `dra ui` 的报告页切「质量」

## 4. 本版要实现的模块功能

- [x] **域名分级**：一手 / 专业媒体 / 一般 / 自媒体，含 docs.*、.edu、.gov、arxiv、github
- [x] **来源打分**：等级 + 数字密度 + 正文长度 + 时效性
- [x] **引用覆盖**：事实句中有多少带 `[n]`
- [x] **数字可核验**：报告中抽出的数字能否在引用来源里找到
- [x] **来源多样性**：域名数、一手占比
- [x] **单项与批量**：`dra eval` / `dra eval --all`
- [x] **页面展示**：质量 tab
- [x] **测试**：分级、打分、评估指标、API

## 5. 本版验收标准

- [x] `domain_tier` 对 arxiv/docs/.edu 返回 3，对 reddit/medium 返回 0
- [x] 新采集的来源带 `tier/tier_label/quality`
- [x] `dra eval` 输出分数、等级、四项指标与警告
- [x] `dra eval --all` 输出基线（26 份、均分 68.8）
- [x] 引用不存在的编号会被计入 invalid
- [x] 页面的质量 tab 能显示分数与未核验数字
- [x] 评估过程不调用任何模型
- [x] 88 个离线单测通过

## 6. 本版风险与待办

- **启发式误报**：数字换了单位（“约 60%” vs “62.1%”）会被判未核验；这是提示，不是判决。
- **只评估不改进**：本版没有用指标反过来约束写作；下一版可让写作阶段“数字必须能回指来源”。
- **等级分布偏低**：基线 26 份 A 仅 2 份，主要输在数字可核验率（33%–100%）。
- **来源分级是静态名单**：新站点默认“一般”，需要持续维护。

## 7. 实测基线（2026-10-21）

| 指标 | 结果 |
|---|---|
| 评估报告数 | 26 份 |
| 均分 / 区间 | 68.8 / 37–90 |
| 等级分布 | A×2、B×13、C×7、D×4 |
| 引用覆盖 | 最好 91%，最差 30% |
| 数字可核验 | 最好 88%，最差 33% |

**结论**：报告“结构上都有引用”，但“数字与来源对不上”仍是主要失分项（修正评估器后重算）。下一步应优先收紧写作阶段的数字来源约束，而不是继续加检索量。

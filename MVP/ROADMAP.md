# ROADMAP · 深度研究代理

> 滚动更新。每个版本的详细范围见对应 `MVP-x.y.md`；本文只回答"下一步做什么、什么算做完"。
> 原则：一次只加一层能力；**能被别人装起来用**，比功能多更重要。

| 版本 | 主题 | 对应原型 / 架构 | 出口标准（Done 的定义） |
|---|---|---|---|
| **0.1** ✅ | 单主题端到端（CLI） | 研究页主流程 + Agent 执行循环 + 工具层 | 3 个主题跑通；报告带可核验引用；trace 可回放 |
| **0.2** ✅ | 可安装可配置（BYOK） | 配置/存储从"开发机"变成"用户机器" | 陌生人 clone → `dra init` → `dra doctor` → 出报告，全程不碰代码 |
| **0.3** ✅ | 本地 UI | 研究页三栏：执行过程 / 报告 / 来源引用 | `dra ui` 只在 127.0.0.1 起服务、自动开浏览器，能看到真实事件流 |
| **0.4** | 知识库 | 知识库页：分类、混合检索、RRF、分块详情 | 报告一键沉淀；关键词 + 语义检索可解释 |
| **0.5** | 历史与追问 | 研究历史页 + 追问树 | 追问复用父 run 的证据，而不是从零再查 |
| **0.6** | 证据质量 | 证据评估：可信度、完整性、交叉验证 | 引用准确率与"结论有依据"可量化，有评测集 |
| **1.0** | 分发与桌面化 | GitHub Release / PyPI / 可选桌面壳 | 一条命令安装；双平台验证；有升级与回滚路径 |

## 与架构图的对应关系

- 0.1 打通：Agent 核心（任务管理雏形 + 执行循环 + 预算）、工具执行层（搜索 / 读取）、
  外部服务（LLM / 搜索 / 提取）、数据存储（Run 产物）、可观测（trace）。
- 0.2 补齐：可靠地"装到别人机器上"——配置、密钥、数据目录、自检、CI。
- 0.3 补齐：前端应用、API 层（本地）、消息与事件系统（SSE）。
- 0.4 补齐：记忆管理（长期）、数据存储（向量索引）。
- 0.5 补齐：记忆管理（任务上下文）。
- 0.6 补齐：证据评估。
- 1.0 补齐：分发、调度、基础设施与安全（按需）。

## 明确不做（或暂不做）

- 多用户、登录、权限、云端部署——这是本地工具，不是 SaaS。
- 自建爬虫 / 反爬对抗（用 Tavily 兜底，必要时再加第三方源）。
- 全量事实核查（成本远高于收益，先做一致性提示）。
- 手机端。

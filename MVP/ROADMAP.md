# ROADMAP · 深度研究代理

> 滚动更新。每个版本的详细范围见对应 `MVP-x.y.md`；本文只回答"下一步做什么、什么算做完"。
> 版本号递增原则：一次只加一层能力，且上一层必须已经可用。

| 版本 | 主题 | 对应原型 / 架构 | 出口标准（Done 的定义） |
|---|---|---|---|
| **0.1** | 单主题端到端（CLI） | 研究页主流程 + Agent 执行循环 + 工具层 | 3 个主题跑通；报告带可核验引用；trace 可回放 |
| **0.2** | Web 实时视图 | 研究页 + 报告 / 来源 / 执行轨迹三个 tab；API 层 SSE | 浏览器里发起研究，能看到真实事件流；刷新后能打开历史 run |
| **0.3** | 知识库 | 知识库页：分类、混合检索、RRF、分块详情 | 报告可一键沉淀；关键词 + 语义检索结果可用且可解释 |
| **0.4** | 历史与追问 | 研究历史页 + 追问树 | 追问复用父 run 的证据与结论，而不是从零再查 |
| **0.5** | 证据质量 | 证据评估：可信度、完整性、交叉验证 | 引用准确率与"结论有依据"可量化；有评测集与基线分数 |
| **1.0** | 多用户与运营 | 认证授权、调度器、监控、Docker 部署 | 多人可用；有并发控制、限额与审计日志 |

## 与架构图的对应关系

- 0.1 打通：Agent 核心（任务管理器的雏形 + 执行循环 + 策略控制的预算部分）、工具执行层（搜索 / 读取）、
  外部服务（LLM / 搜索 / 提取）、数据存储（Run 产物）、可观测（trace）。
- 0.2 补齐：前端应用、API 层、消息与事件系统（事件流）。
- 0.3 补齐：记忆管理（长期）、数据存储（向量索引）。
- 0.4 补齐：记忆管理（任务上下文）。
- 0.5 补齐：证据评估。
- 1.0 补齐：调度器、基础设施、安全与合规。

## 明确不做（或暂不做）

- 移动端、多语言界面。
- 自建爬虫 / 反爬对抗（用 Tavily 兜底，必要时再加第三方源）。
- 全量事实核查（成本远高于收益，先做一致性提示）。
